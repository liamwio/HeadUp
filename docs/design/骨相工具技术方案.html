骨相工具技术方案

从一张正面照到一个类型名，中间要解决四件事：尺度归一化、姿态污染、量感与线条的可计算定义、以及阈值从哪来。本文给出可实现的答案。

验收指标 主型重测一致性 ≥ 90% 推理 小程序服务端 / App 端侧 留存 原图内存内处理，不落盘 分类 规则引擎 + 滞后带
要点

四个技术决定

决定一 · 所有指标都是比值

不需要知道照片的真实尺度，因为没有一个指标是长度。

每个指标都是同一张图内两个量的比（长度比、面积比、角度）。尺度在分子分母里自动约掉——这消灭了单目视觉最麻烦的标定问题，也是本方案不需要参照物、不需要深度传感器的根本原因。

决定二 · 双轨推理，原图不落盘

小程序走服务端推理；App 走端侧推理。两条轨道共用同一套特征与分类代码。

小程序端侧 ML 的机型覆盖不可依赖，因此小程序路径直接采用服务端推理，不为端侧方案赌运气。代价是原图必须上传——用内存内处理、全程不落盘、算完即弃把代价压到最小：服务端计算完成后只保留 ~40 个无量纲数字，原图不写磁盘、不入对象存储、不留备份。

需要真正端侧闭环的用户走 App 版（后续阶段），同一套算法本地跑，照片不离开设备——这是 App 版唯一但足够的差异化理由。

决定三 · 姿态是一等公民，不是预处理

头位偏转污染比例轴，表情污染线条轴，光照污染量感轴——三者各毁一个类型轴。

所以姿态估计不是「清洗一下」，是采集阶段的准入门：不合格直接拒收重拍，绝不「尽力算一个」。见 §04。

决定四 · 阈值是标定出来的，不是设计出来的

本文档不给任何一个类型分界的具体数值。

三轴的分界点是标定集分布的分位数，再用人工标签校正；滞后带宽度 δ 是让重测一致性达到 90% 所需的最小值，由重测数据反解得出。它们是标定流程的输出，不是输入。见 §07。

服务端推理的成本，比直觉低一个量级

Face Mesh 是轻量模型，服务端单次推理约 10–30 ms，加解码与预处理按 0.3 s 估。在目标规模（月 28,000 次扫描，对应月收入 5 万）下：

计算 ≈ 28,000 × 0.3 s × 0.5 GB ≈ 4,200 GBs   // 通常在云开发免费额度内
带宽 ≈ 28,000 × 300 KB ≈ 8.4 GB/月
合计 ≈ 数十元至低百元 / 月                    // 相对收入可忽略

结论：「零边际成本」这条支柱基本保住——不是零，但小到不影响商业模型。

前提是端侧压缩到位。若上传未压缩原图（3–8 MB），带宽与解码成本上升一个量级，且延迟不可接受。压缩步骤是硬性要求，不是优化项。

双轨的工程约束：一套算法，两个宿主

特征计算与分类必须写成与宿主无关的纯函数模块（输入 468 点坐标数组，输出指标向量与类型），才能在云函数与 App 端复用同一份实现。

若两轨各写一遍，会出现同一张脸在小程序和 App 上得到不同类型——这比任何精度问题都致命。纯函数模块 + 共享测试向量（黄金样本的输入输出对）是硬性要求，两轨必须对同一组测试向量给出逐位一致的结果。

Face Mesh 不提供可靠的发际线（点 10 是额顶而非 trichion，且受发型遮挡影响）。因此本方案不计算传统「三庭」，改用不依赖发际线的等价量：

// 全部以 glabella→menton 为纵向单位，跳过上庭
midfaceRatio = dist(glabella, subnasale) / dist(glabella, menton)
lowerRatio   = dist(subnasale, menton)   / dist(glabella, menton)
faceIndex    = dist(glabella, menton)    / bizygomaticWidth

这既避免了最大的一个不稳定源，也让指标对发型完全免疫——而发型恰恰是用户会改变的东西，若指标随发型漂移，重测一致性直接崩。

采集

采集协议

目标不是精度，是防止类型跳变。三个污染源各自对应一个类型轴，因此三道门缺一不可。

正面照 · 三门
门判据阈值污染谁实现
姿态 yaw / pitch / roll 各 ≤ 3° 比例轴 P PnP 求解（下方）；实时用轻量代理，快门后精算
表情 口部开合比、口角上扬、眼裂开合 中性带内 线条轴 L 口内高/口宽 ≤ 阈值；口角连线相对水平倾角 ≤ 阈值；眼裂高/宽在正常睁眼带内
光照 左右半脸亮度差、整体过曝/欠曝、面部对比度 标定得出 量感轴 W 面部掩膜内直方图统计；侧光会伪造骨点显露度
距离 面高占画幅比 区间约束 全部 太近有透视畸变，太远点位噪声大
妆容 浓度估计 不设门 线条轴 L 提醒不拦截 见下方专节

姿态求解

// 精算：canonical_face_model 的 3D 点 + 检测到的 2D 点
solvePnP(objectPoints_3D, imagePoints_2D, K, dist) → rvec
Rodrigues(rvec) → R  →  Euler(yaw, pitch, roll)

// K 未知时用近似：fx = fy = imageWidth, 主点取图像中心，dist = 0
// 对 ±3° 量级的判定，这个近似足够；不要为此引入相机标定

// 实时粗筛（每帧跑，代价低）
roll  ≈ atan2(dy, dx) of (outerCanthus_L → outerCanthus_R)
yaw   ≈ 由 |noseTip→oval_L| / |noseTip→oval_R| 偏离 1 的程度估计
pitch ≈ 由 midfaceRatio 偏离个体基线的程度估计  // 最弱的一维
pitch 是最难的一维

单目 2D 对俯仰最不敏感，而俯仰恰好直接改变纵向比例（P 轴）。两条缓解：

  1. 用 PnP 精算而非几何代理做最终判定——代理只用于实时引导。
  2. 引导设计上物理约束俯仰：屏幕给水平参考线，要求双眼与耳屏连线对齐；配合「手机与视线等高」的文案提示。物理约束比算法校正可靠。

妆容：提醒，不打断

妆容与姿态是两类问题，处理方式必须不同

头位超限产生的是垃圾数据，必须拒收；妆容不是——它是这个人真实的呈现方式，而且是绝大多数目标用户的常态。对妆容设门会直接杀死漏斗。

因此：采集页给一句静态提示，结果页给一条条件提示，推理全程不中断。

// 1. 采集页（常驻，不判定）
提示文案 = "素颜或淡妆，结果更准"

// 2. 结果页（仅在检测到浓妆时出现）
if makeupIntensity > 阈值:
    注记 = "检测到较明显妆容，线条判定已自动侧重下颌轮廓"
    // 不降级、不拒绝、不要求重拍

// 3. 算法侧：L 轴自适应加权（关键）
//   眉形 / 唇峰 / 眼型 → 妆容可大幅改变
//   下颌轮廓         → 修容只能改明暗，改不了轮廓关键点位置
if makeupIntensity > 阈值:
    L_score = w_jaw' · z(jawSharpness) + …     // 提高 jaw 权重
else:
    L_score = 标准权重

下颌轮廓基本免疫妆容——修容改变的是阴影，不是轮廓关键点的几何位置。所以 L 轴在浓妆下可以优雅降级：牺牲一点分辨率，换取判定不崩。

makeupIntensity 的估计方式与阈值在 S1 标定时确定（同人素颜/化妆对照组）。若对照组显示妆容对 L 轴影响小于预期，可退化为仅保留采集页提示，不做自适应加权。

拒收逻辑

  • 实时门不过 → 快门置灰 + 指向性提示（「下巴略收」「向左转一点」「光线偏右侧，请正对光源」）
  • 精算门不过 → 拒收并说明原因，返回取景，不保留该次结果
  • 绝不做「尽力算一个」——一次勉强的结果会污染重测一致性，也会让用户拿到一个她会分享出去的错误类型

归一化

// 步骤 1：去 roll —— 绕图像中心旋转，使双外眦连线水平
θ = atan2(P263.y - P33.y, P263.x - P33.x)

// 步骤 2：定义两个基准量（同图内，单位任意）
W_zyg = 面部外轮廓链上的最大水平跨度        // 颧宽，量感与横向指标的分母
H_gm  = dist(glabella, menton)              // 纵向基准，比例指标的分母

// 步骤 3：所有指标 = 比值 / 角度 / 面积比  →  尺度自动约掉
// 不做绝对长度归一化，不需要参照物，不需要相机标定
为什么用外轮廓极值而不是固定点求颧宽

固定用 234 / 454 会在不同脸型上落到不同解剖位置——脸型偏长的人最宽处在颧弓，偏方的人可能在下颌角。取轮廓链的 x 极值才是真正的「面部最宽处」，且顺带给出一个免费信息：最宽处的纵向位置——它是「颧骨高位 vs 下颌宽」的判别量，直接喂给量感轴。

特征

特征管线 A–F

共 ~40 个指标。以下给出定义与算法；所有分界阈值见 §08，此处不出现任何数值。

A · 比例

midfaceRatio  = |glabella→subnasale| / H_gm
lowerRatio    = |subnasale→menton|   / H_gm
faceIndex     = H_gm / W_zyg                      // 面长宽比
fiveEyeRatio  = eyeFissureWidth_mean / W_zyg      // 五眼比
interocular   = |innerCanthus_L→R| / W_zyg
lipChinRatio  = |stomion→menton| / |subnasale→menton|

B · 量感

三个分量，标准化后加权合成。

// B1 五官面积占比（多边形面积用 shoelace）
featureAreaRatio = (A_eyes + A_brows + A_nose + A_lips) / A_faceOval

// B2 五官尺度指数（四个横向比的均值）
featureScaleIdx = mean(
  eyeFissureWidth / W_zyg,
  alarWidth       / W_zyg,
  mouthWidth      / W_zyg,
  browLength      / W_zyg )

// B3 骨点显露度（2D 代理，三项）
zygoGonialRatio = W_zyg / W_gonial              // 颧宽 / 下颌角宽
maxWidthHeight  = (y_maxWidth - y_glabella) / H_gm   // 最宽处的纵向位置
jawSharpness    = 见 C 组                        // 复用

W_score = w1·z(B1) + w2·z(B2) + w3·z(B3)         // z = 标定集 z-score
B3 是全表最弱的一项

「骨点显露度」本质是三维信息，2D 代理必然有限，且对光照高度敏感——侧光会伪造出骨感。这是光照门存在的唯一理由。

标定时若发现 B3 与人工标签相关性显著低于 B1/B2，降低 w3 甚至归零，用 B1+B2 撑量感轴。宁可少一个弱信号，不要引入一个噪声源。

C · 线条

核心是下颌轮廓的曲率分布——「有明确转折」还是「均匀圆弧」。

// 1. 取 FACE_OVAL 下半段（左下颌角 → 颏 → 右下颌角），等弧长重采样为 N 点
// 2. 离散曲率：用三点外角
for i in 1..N-2:
    v1 = P[i]   - P[i-1]
    v2 = P[i+1] - P[i]
    κ[i] = angleBetween(v1, v2) / (|v1| + |v2|) * 2

// 3. 尖锐度 = 曲率的集中程度，而非曲率大小本身
jawSharpness = max(κ_gonialRegion) / mean(κ_all)
//   高 → 曲率集中在下颌角 = 有明确转折 = 直
//   低 → 曲率均匀铺开     = 圆弧过渡   = 曲

// 4. 辅助项
browCurvature = |a| of 二次拟合 y = ax² + bx + c  (眉弓链，归一化后)
eyeTilt       = 内外眦连线相对水平的角度
eyeAspect     = eyeFissureHeight / eyeFissureWidth
cupidSharp    = 唇峰点处的外角

L_score = w1·z(jawSharpness) + w2·z(browCurvature⁻) + w3·z(cupidSharp) + …
// 浓妆时切换到 jaw 主导的权重组，见 §04
为什么用「曲率集中度」而不是「曲率最大值」

曲率最大值会被脸的大小和轮廓采样密度污染。比值形式（局部最大 / 全局均值）是无量纲的，且直接对应「有没有一个角」这个感知问题——一个圆脸和一个方脸的绝对曲率可能接近，但分布形态完全不同。这是 C 组能否成立的关键设计。

E · 对称性

midline = 由 glabella、subnasale、menton 拟合的中轴线
for each 成对特征:
    asym = |d_left - d_right| / (d_left + d_right)    // 归一化差异

eyeHeightAsym, eyeSizeAsym, nasalDeviation,
mouthCornerAsym, jawContourAsym  →  取加权合成 + 各项单列

E 组不进类型轴，仅作报告读数。展示时必须给人群参考区间——几乎所有人都有轻度不对称，报告绝不能出现「异常」类判定措辞。

F · 分区平衡

差异化最强的一组，且实现成本最低——它是 A/B/C 的二次计算。

// 纵向量感一致性：分别算上/中/下三区的局部量感，取离散度
W_upper = 眉眼区特征面积 / 该区面部面积
W_mid   = 鼻颧区特征面积 / 该区面部面积
W_lower = 唇颏区特征面积 / 该区面部面积
regionalWeightSpread = std(W_upper, W_mid, W_lower) / mean(...)

// 线条一致性：上半脸线条语言 vs 下半脸
L_upper = f(browCurvature, eyeAspect, eyeTilt)
L_lower = f(jawSharpness, cupidSharp)
lineCoherence = |z(L_upper) - z(L_lower)|

// 输出三个可直接驱动建议的标签
balanceType ∈ { 上重下轻, 均衡, 上轻下重 }
lineConflict ∈ { 一致, 轻度冲突, 明显冲突 }
F 组的工程价值

它把「说不上哪里不对」变成两个离散标签，而每个标签直接映射到一条明确建议（发型补下半部体积 / 顶区蓬松 / 妆容统一线条语言）。零新增采集、零新增模型、复用已有指标——投入产出比全表最高。

分类

分类引擎与滞后

// 三轴各得一个连续分，映射到 [0,1]
W_score → 量感   分 3 档：轻 / 中 / 重   （2 个分界 t_W1, t_W2）

滞后带：稳定性的全部来源

// 每个分界 t 配一个死区 ±δ
if |score - t| > δ:
    档位 = 硬判定
    confidence = "clear"
else:
    // 落在死区 → 两级处理
    if 存在该用户历史结果:
        档位 = 沿用历史档位              // 粘滞，直接消灭跳变
        confidence = "sticky"
    else:
        档位 = 就近判定
        confidence = "borderline"
        输出措辞 = "偏{邻档}的{本档}型"   // 不硬分
三条设计要点
  • 粘滞是最便宜的一致性来源。同一 openid 的历史结果做锚，边界附近直接沿用——这一条几乎白送几个百分点的重测一致性，成本是一次数据库读。
  • 「偏 X 的 Y 型」不是妥协，是产品特性。它比硬分更真实，用户也更容易接受；同时它把边界样本从「错误」重新框定为「过渡态」。
  • δ 不是拍脑袋定的——它是让重测一致性达标的最小值，从 §09 的重测数据反解。δ 越大越稳但越模糊，取刚好达到 90% 的那个值。
如果 12 型撑不住

凝/舒轴（比例）最容易受 pitch 残差污染，是三轴中最不稳的一个。若 W8 全名一致性低于 80% 且无法通过收紧 pitch 门解决：

降级方案——把凝/舒从类型名里拿掉，降为报告读数。对外只做 6 主型。这个降级不损伤传播（本来对外就只用 6 个名字），只损失一点报告精度。宁可粗但稳。

标定

标定方法学

阈值不能设计，只能标定

任何在这份文档里出现的具体分界数值都会是编造的。三轴分界 t_W1 t_W2 t_L t_P 与死区 δ 必须从数据得出，流程如下。

三阶段标定
阶段样本量时点产出方法
S1 维度验证30–50W3–4 确认三轴能否分开真实人脸 人工标注 → 看每轴的类间可分性。这一步验证的不是数字，是维度选对没有
S2 初始阈值150–300W5–7 t_W1 t_W2 t_L t_P 初值 分位数起步（量感取三分位、线条与比例取中位），再用人工标签做一维搜索最大化一致率
S3 死区求解30 人 × 3 次W8 δ 在重测集上扫 δ，取满足一致性 ≥ 90% 的最小值
S4 线上重标≥ 1000上线后 用真实分布替换标定集分布 用真实用户指标分布重算分位数。换阈值前必须评估存量用户类型变更的影响
30–50 张不足以定阈值

12 个类别、30–50 个样本 = 每类 2–4 个，定不出稳定阈值。业务手册里 W3–4 那道门的真实作用是验证维度——若反复出现「这张说不清是修竹还是春山」，要改的是判据不是分界线，而且必须在写代码之前改。

阈值需要 S2 的 150–300 张。标注由你自己做（标注者内部一致性比人数重要）。

标定集从哪来

首选：用自己的内容账号招募

W3–4 你已经有一个正在涨粉的小红书账号。它就是标定集的最佳来源。

「参与内测，免费获得完整报告」——成本为零，且这条路径在技术上优于任何外部图源：

  • 分布正确。阈值是分位数，分位数只在与真实用户同分布的样本上才有意义。你的关注者就是你的用户；网上随机人脸不是。用错分布标定的阈值，上线当天就要重标。
  • 可控采集。你能要求按 §04 的门限拍——姿态、光照、中性表情、素颜/化妆对照组。外部图源做不到，而不合门限的照片对标定毫无价值。
  • 可复访。同一批人还能直接用于 §09 的重测研究（30 人 × 3 次本来就要招募真人），两件事一次招募解决。
  • 顺带是内容素材与首批种子用户。

补充来源（按可用性排序）

  1. 合成人脸——生成式模型产出的非真实人物face，无肖像与同意问题，可按需要的量与人群特征批量生成。适合把样本量从 150 补到 300+，用于分布形状而非绝对定标。注意：生成模型有向训练分布回归的倾向，可能压缩极端量感样本——只用于填充中段，两端仍靠真人。
  2. 明确授权可商用的人像数据集——逐个核对许可条款，注意多数学术人脸数据集仅限研究用途，不覆盖商业产品标定。
  3. 线下有偿招募——签拍摄同意书，单价可控，适合补齐稀缺档位（重量感样本通常最少）。
抓取网络人脸这条路我不做，也建议你不做

不是许可证技术性问题。人脸属敏感个人信息，采集须取得单独同意，抓取真实可识别个人的面部图像用于商业产品标定，在 PIPL 下没有可用的合法性基础——这正是 Clearview AI 在多个法域被处罚的行为类型。

更要命的是位置：标定集是产品的地基。全部阈值都从它导出，事后无法「删掉重来」——只要它在，整个产品的每一个判定都长在它上面。而这个项目的全部商业逻辑（§11 的隐私卖点、不做医美导流、不碰未成年人）建立在合规干净上，在地基里埋这个东西，是拿最大的一件事换最省的一星期。

而且它在技术上也不划算：网络随机人脸与你的目标人群不同分布，姿态光照不可控，无法做素颜/化妆对照——用它标定出的阈值，上线后照样要用真实用户数据重标一遍。省下的那一星期最终还是要还。

S4 的陷阱：改阈值会改变已发出的类型

用户已经把「我是琥珀」发到社交平台了。线上重标若让她变成「墨玉」，那是产品级信任事故。

处理规则：已生成的报告与类型永久锁定其生成时的阈值版本（报告记录 calibVersion），新阈值只作用于新测。除非发现严重错误，否则不做历史回溯重算。

验证

重测一致性验证

这是唯一的硬性验收，也是 W8 那道门。

协议

  • N = 30 人，覆盖三档量感（每档 ≥ 8 人），否则测不出边界行为
  • 每人 3 次独立会话，间隔 ≥ 1 天，每次重新取景、换环境光、允许换发型与妆容——这正是真实使用条件
  • 每人产生 3 个配对（1-2, 1-3, 2-3），共 90 对
主型一致性 = (同主型的配对数) / 90        // 目标 ≥ 90%
全名一致性 = (同全名的配对数) / 90        // 目标 ≥ 80%

// 关键：必须分轴统计，否则不知道该修哪里
量感轴一致性 = 同档配对 / 90
线条轴一致性 = 同档配对 / 90
比例轴一致性 = 同档配对 / 90
分轴统计是这一节的核心

总体一致性只告诉你「不达标」，分轴一致性告诉你哪一轴在漏，而每一轴对应一个明确的修法：

  • 量感轴漏 → 光照门太松，或 B3 骨点显露度在制造噪声（考虑降权/归零）
  • 线条轴漏 → 表情门太松（口角与唇峰对表情极敏感），或轮廓链取点有误
  • 比例轴漏 → pitch 残差，收紧俯仰门或强化物理引导；仍不行则执行 §07 的降级方案

同时监控的反向指标

每次收紧门限都要重测采集一次通过率。若为达到 90% 一致性必须把通过率压到 70% 以下，说明判据本身不够稳健——回到 §06 改判据，不要继续收门。这是本方案最重要的一条工程纪律。

措辞是硬约束，不是文案偏好

输出一律描述表面形态，不做解剖学断言。写「中面部表面饱满度」，不写「上颌骨饱满度」。

依据：软组织形状并不紧密跟随骨性结构，中面部尤弱——上唇与上颌之间的形状预测力仅约 9.6%，且骨性越不足者该区软组织往往越厚，两者互相抵消。这不影响造型用途（造型响应的是可见形态），但它决定了报告能写什么。报告应显式包含一句：「中面部的骨性投影需要影像检查，本报告只描述表面形态。」

侧面照的姿态门必须更严

侧貌角度对头位极敏感——偏转几度，所有角度量全变。约束手段：

  • 自然头位提示 + 屏幕参考线（耳屏与眶下缘连线水平）
  • 要求耳廓完整可见（作为「确实是正侧位」的几何证据）
  • 检测到对侧眼可见 → 判为斜位，拒收

降级方案：若侧面重复性达不到要求，退回只用正面 + 只做类型学，不发布侧貌数值。付费层改以造型策略深度作为价值主张。这是可控降级，不是全案失败。

不能再说「我们看不到你的脸」——那句话在小程序路径上不成立。但仍有一句真话，而且几乎一样强：

照片在内存里算完就丢，从不落盘；我们存下来的只有 40 个还原不出人脸的数字。

这比对标站的「原图 2 小时内删除」更进一步（它意味着原图确实写过盘）。可直接写进产品页。合规做成卖点，而不是做成负担——但前提是这句话必须真，所以「不写磁盘、不进日志、不留备份」是代码级要求，要在 code review 里逐条确认，不能只写在隐私政策里。

App 版则可以恢复完整的「照片不离开设备」表述——这也是 App 版存在的主要理由。

合规要点

  • 人脸信息属敏感个人信息，需单独同意——不能混在通用用户协议里勾选
  • 提供一键删除全部数据的入口，且真实执行
  • 产品与协议层明确面向成年人，主动排除未成年人（不满十四周岁的个人信息另有专门处理规则，solo 阶段不承担）
  • 上传前必须明确告知「照片将用于本次计算，计算完成立即丢弃，不作留存」并取得单独同意
  • AI 造型图分支是唯一留存原图的链路，必须再次单独同意，不可与上一条合并
  • 报告与文案层：不打分、不给「与理想值的差距」、不做解剖学断言、不承诺效果、不推荐医美项目
