# 开发与源码上传约定

## Git 分支

本机开发目录为 HeadUp-AppOnly，工作分支 app-only-photos；GitHub 默认 main 与首次上传时的应用内保存版一致。本机 main 保留分支拆分前的历史基线，不要直接把它覆盖推送为远端 main。

后续修改在 app-only-photos 或新功能分支提交，通过合并更新远端 main。不要使用强制推送覆盖远端工作。

## 拍摄与测量

照片写入应用内数据库。目录复制适配器禁用，Android 原生 photo-copy 方法拒绝旧页面调用。不处理旧版公共目录待保存队列。已有原图和测量历史不可静默覆盖。

关键点、绘线和读数必须来自同一套保存的几何数据。更换模型、点位语义或公式后要更新来源版本，并禁止跨不兼容版本直接计算趋势。

UI 变更先保存并展示同尺寸前后对比，再按项目规则构建新 Android 版本。每次更新保留旧 APK，递增版本。

## 外部数据与模型

默认测试使用合成夹具，不需下载儿童照片。研究页和部分 scripts 命令依赖未分发的数据集，需自行取得使用授权并放在本机被忽略的 data 目录。

仓库保留约80MB运行资源，单个文件小于GitHub普通Git文件上限。增长为大模型时再单独设计资源下载或LFS策略；不要把SDK、node_modules和APK加入Git。

## 可选服务

个人版本默认不需要家庭账号后端。调试可选服务时先查看 .env.example、.env.ai.example、.env.family.example，再配置自己的本机文件；家庭同步与云端AI设置不意味着照片被授权上传。

## 发布范围

只上传应用源码、必要运行资源、工程配置和维护文档。真实照片、用户数据库、密钥、签名文件、日志、构建结果和研究测试报告留在本机。初次发布前检查当前文件和历史提交，避免仅在最新版本删除敏感内容却保留在Git历史中。
